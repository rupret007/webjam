# First hands-on test

Use the identified draft build and keep its `SOURCE-AND-HASHES.json` with your
results. Start a copy of [the pilot record](FOLLOW_ALONG_PILOT_RECORD.md).
You need two people, headphones, a YouTube lesson and a Webex meeting. Start
on the same Wi-Fi or local network: default Art invitations use a private
network address. Separate-home reachability needs its own test and a room
both computers can reach.

Before following the clicks below, let each person try Host or Join without
coaching. Record time to the first shared lesson, confusing labels and any
help needed. Then use these instructions to finish the test. No recording is
needed; capture screenshots or recordings only with participants' consent.

## Paint Along first

1. Choose **Art**. The host chooses **Paint along** and hosts a room, then
   uses **Copy Invite**. The guest chooses **Join** and pastes that invitation.
2. Choose **Watch a shared lesson**. The host chooses **Choose YouTube…**,
   pastes the lesson link, then chooses **Open in browser**.
3. In Conversation, the host uses **Add Link** for the Webex meeting, then
   **Copy Link** to send it to the guest. The guest uses **Add Link** (or
   **Change Link**) in Conversation. Both choose **Join / Open Meeting**.
   If the original room invitation already contained this meeting link,
   there is no need to add it again. A meeting link added later does not
   update an invitation already sent; share it explicitly without rejoining
   the WebJam room.
4. The host shares the browser lesson with computer sound enabled (or a
   browser tab with tab audio in the Webex web client). Keep participant
   videos visible. The guest watches and hears that shared presentation and
   leaves their own audible YouTube copy closed.
5. Confirm lesson sound and both voices by listening. Paint with real
   materials. Also try your preferred painting app using Webex screen
   sharing, then deliberately return to the lesson share.
6. Ask for a pause; the host pauses the actual browser player, then resumes.
   Use the pause-request controls in supported LAN Art rooms, or ask by
   voice/chat. Visit **Notes**, then return through **Conversation**. Confirm
   the chosen lesson remains. The host uses **Remember lesson** to save it.
   For the guest's restart check, the host sends the YouTube URL separately;
   the guest opens **Session library → Art project → Add link…**, adds that
   reference and chooses **Save**. References are local to each workspace.
7. Restart WebJam and **Continue** the saved workspace. This restores local
   work. Choose **Start Session**: a saved host starts a room; a saved guest
   gets **Join** and pastes a fresh host invitation. Once connected, open
   **Session library**, select the Art reference and choose **Use saved
   lesson**. Stay in this continued workspace throughout. Confirm the lesson
   returns to setup without automatically opening or playing media.

For a failed connection, follow the room's recovery controls: **Try again**
retries the connection; **Paste new invite** replaces a rejected invitation.
Keep your saved workspace. A later meeting-link change uses **Copy Link** and
**Add Link / Change Link** rather than a new room invitation.

## Music video practice

After the Art test, end or leave that room and use **File → Return to launch…**.
Choose **Music**, then **Host** to open the workspace. Choose **Play along →
Set up video practice**; audio setup need not finish first. Add the meeting
link and use **Copy Link** to send it. Guests can open this link directly in their
browser or meeting app; it is not an invitation for WebJam's **Join** field.
People already in a WebJam room can use **Add Link / Change Link** in
Conversation. Share one song through Webex, listen and take turns.

This practice can continue if Jamulus setup fails: a WebJam room and Jamulus
are not required for the meeting presentation. Its audio is delayed. If an
instrument is already connected to Jamulus, it can still transmit; listening
mute does not stop that send. Stop the instrument at its send control when
appropriate and verify the result by listening.

Live ensemble is a separate test. The supported host setup uses **Open Shared
Track**, a permitted local audio file and certified BlackHole routing on
macOS. Guests use **Open Jamulus mixer**. Disconnect Webex audio while playing,
keep video for faces, and judge timing by Jamulus sound. Follow the full
[two-person acceptance procedure](PAINT_PLAY_ALONG_PLAN.md#two-person-acceptance)
before claiming good ensemble latency.

## Record the result

Mark each physical observation **PASS**, **FAIL** or **NOT RUN** in the pilot
record. Include OS, Webex client, audio hardware, role, exact click, expected
result and actual result for failures. Do not put private invite links or
meeting credentials in public reports. See [TEST_PROCEDURE.md](../TEST_PROCEDURE.md)
for additional recovery and routing checks.
