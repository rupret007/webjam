# Private music acceptance worksheet

Updated November4, 2026. The original November3 audit described proposed source
paths; it did not establish physical music. This worksheet follows current
source through native423 and the pending native424 lifecycle candidate. It
creates no deployment, provider or release approval.

Use the canonical [creator guide](../USER_GUIDE.md) for installation and normal
Host/Join controls. [Web Join](web-join.md) describes the separate browser guest
and [adaptive latency](adaptive-latency.md) describes its measurement limits.
A source lab, synthetic tone, transport counter or mocked Connected label does
not establish reciprocal audible music.

## Admission before any trial

- Use an exact qualified frozen build: source/build ID, archive filename/hash,
  platform/architecture, bundled target and normal trust checks. The private
  browser destination must be build-bound to `private-beta`. Do not rewrite an
  invitation, override frozen metadata or borrow a source checkout's behavior.
- The infrastructure owner must establish actual combined billing-period
  headroom, intended separate browser TURN credentials, exact origins and
  private delivery/rollback. A configured app allowance is not an account-wide
  provider spending cap. Keep AI and separate Hang Out chat/media TURN off.
- Obtain current capture consent and wired-headphone readiness on both devices.
  Use the musician's intended interface and Jamulus's native sound setup.
  Check microphone or Join can request browser microphone access; capture
  remains opt-in and music processing intentionally keeps echo cancellation off.
- A protected browser guest first enters the private community in the same
  browser, then opens the complete host invitation through the normal path.

The approved trial scope is **one native host and one browser guest at a time,
no more than ten minutes per trial**, after the preceding gates. No purchases,
signing-service enrollment or public launch. Recording is not authorized by
this worksheet and is not required as a substitute for listening.

Each row is a separate bounded trial. Two directions of audibility are required;
one-way sound or same-machine echo is insufficient. Browser delay and ensemble
usability require actual listening; the estimated60–120ms copy is not a result.

A native-to-native comparison is a separate future scope, not a prerequisite
that expands this one-host/one-browser authorization. Current unsigned Windows
packages cannot qualify native remote Music under the existing signature
policy. A Windows browser trial does not establish Windows native hosting/join.
Do not bypass that policy or replace native evidence with WSL.

## Normal route and recovery

Use the qualified package's existing Host/Join route from the creator guide.
The documented version2 LAN protocol is not proof that the current frozen
launcher exposes a LAN selector. The normal remote path selects its owned
sidecar; removing it, faking frozen/platform flags, rewriting invitations or
using a manual public Jamulus server does not qualify that product path.
Tailscale100.x addresses are administration addresses, not an eligible browser
ICE or version2 LAN workaround. Same Wi-Fi does not remove browser TURN issuance.

For each admitted trial, observe initial entry, explicit guest permission,
reciprocal live sound, a brief playing interval, deliberate guest Leave/host
Stop and a fresh normal Join where permitted. Respect one-use invitations and
ask the host for a fresh one when required. Record interruption/device-recovery
behavior without silently reusing consumed invitations or extending the trial.
A failed gate remains failed or NOT RUN; retain its cause and stop capture.

## Current latency mechanisms and limits

| Mechanism | Current source behavior | What a trial can establish |
| --- | --- | --- |
| Dedicated Jamulus profile | Optional defaults fill only unset supported keys; disabled tuning/player override does not write. Preserve musician values and unknown formats. | Record the actual Jamulus UI device/buffer/jitter selection; source preferences are not hardware measurements. |
| Native future recommendations | A qualified scoped ping may persist a later-launch frame recommendation. Jamulus3.12.2 has no RPC live buffer setter. Stop/rebind retires old callbacks; profile errors disable optional stepping for that launch. | No claim that the current live buffer changed merely because a preference was saved. |
| Native displayed estimate | Uses the launch preference and a fresh exact numeric launch-target ping. Wrong server, hostname/sidecar, disconnected, stale or retired observations remain unknown. | Does not measure the remote Pion path or overall audible delay; per-remote-player metrics remain unqualified. |
| Browser receiver | Initial `jitterBufferTarget` **20 milliseconds**, adapting within20–120ms with rate limiting when supported; closed sessions cannot tune a retired receiver. | Record supported constraints and listening results separately; it is not a setting in seconds or a WAN measurement. |
| Browser/host codec bridge | Standard WebRTC Opus converts to Jamulus custom128-sample frames through the host-owned bridge. Missing custom Opus fails closed. | The normal package must allocate and stop the real bridge; a source-only codec lab is insufficient. |
| Credential/session lifetime | Effective expiry is bounded by the host invitation and issued credentials; stop at ten minutes or earlier. | Record actual expiry/Leave behavior; no extension or quota bypass. |

See the source-bound [adaptive mechanisms](adaptive-latency.md) and
[network/deadline contract](web-join.md) for exact bounds. The server-jitter
injection hook currently has no production caller. Do not invent dropout counts
or per-player delay when the interface does not expose them.

## Private evidence record

For each row retain UTC start/end, exact source/build/archive hashes and target,
OS/architecture/browser, intended input/output and headphone confirmation,
ordinary admission result, each direction's human hearing confirmation, timing
feel, measured delay only if actually measured, dropout observations, Leave/Stop
and recovery. Mark unavailable metrics unknown. Preserve original failures.

Do not retain invite URLs/fragments, TURN/RPC credentials, cookies, raw mailbox
messages or private filesystem paths in shared evidence. Logs must be bounded
and redacted; unexpected capture or failed cleanup leaves the row incomplete.

Completion requires observed chat and actual music through the advertised
paths. This worksheet and CI do not claim any physical row has passed.
