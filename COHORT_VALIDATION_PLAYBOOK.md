# WebJam v0.16 closed-pilot playbook

## What to tell musicians

“WebJam starts or joins the private rehearsal. Jamulus carries the music.
Choose your interface and buffer in Jamulus. Webex is optional for talking or
video. Recording and Studio are available when you need them, not before.”

## Run order

1. Verify the exact v0.16 package identity from the pilot worksheet.
2. Host chooses **Host a Jam**; guest uses one invite.
3. Each musician completes native Jamulus setup and explicitly confirms
   audibility.
4. Add/skip Webex only after music is ready.
5. Record a short shared take; separately opt into Local Originals only if
   desired.
6. Review/export in Studio and record the actual result.
7. End safely and record process/recovery outcome.

## Observe, do not infer

Record direct observations for two-way audibility, device changes, sleep/wake,
recording finalization, Local Originals transfer, and external-editor import.
Do not infer a PASS from a meter, a process, or a package-only test.

## Escalation

For sound problems, foreground Jamulus and use its Audio/Network Settings. For
Webex problems, keep the music session usable and diagnose Webex separately.
For a failed take, preserve the media and use Support only if requested.
